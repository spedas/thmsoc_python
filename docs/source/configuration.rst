Configuration
=============

The repository includes ``example_thmsoc_python_config.toml``. Copy it to
``thmsoc_python_config.toml`` at the repository root, then customize the input
and output paths for your environment.

On Windows, use forward slashes or doubled backslashes in TOML paths because a
single backslash begins an escape sequence. On the THEMIS lab machines,
``/disks/themisdata`` may be used for input, but development output should point
to a location where your account has write permission.

IDL jobs
--------

The ``[idl]`` table selects the IDL executable, startup procedure, and search
path. The ``[environment]`` table contains additional variables copied into
child processes. See ``example_thmsoc_python_config.toml`` for the production
layout. These settings are applied to a copy of the calling process's
environment; calling :func:`thmsoc.run_idl` does not modify ``os.environ``.

Run an existing batch file and combine standard error with its log::

   from thmsoc import run_idl

   result = run_idl(
       "runoff_l2gen.bm",
       cwd="/path/to/work",
       stdout_path="/path/to/logs/runoff.log",
       stderr="stdout",
       check=True,
   )

Source generated by Python can be supplied directly::

   result = run_idl(
       source="print, 'hello'\nexit\n",
       cwd="/path/to/work",
       keep_batch=False,
       check=True,
   )

The generated ``.bm`` file is removed after success and retained after failure
for diagnosis. Set ``keep_batch=True`` to retain it unconditionally. IDL errors
do not necessarily map to a nonzero process status; ``check=True`` checks the
status returned by the installed IDL executable.

For asynchronous work, use ``wait=False`` and retain the returned job::

   job = run_idl(source=batch_source, cwd=work_dir, wait=False)
   # Other Python work can happen here.
   return_code = job.wait(check=True)

``stdin``/``stdin_path``, ``stdout``/``stdout_path``, and
``stderr``/``stderr_path`` control the standard streams independently.
``append=True`` appends to path-based logs instead of replacing them. Per-job
``executable``, ``startup``, and ``environment`` arguments override configured
values.
